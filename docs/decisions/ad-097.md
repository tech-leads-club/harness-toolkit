# AD-097 — The shell layer goes, and with it every platform branch that only existed because of it

- **status**: active

## Decision

1. **`install.sh` and `install.ps1` are deleted.** The package is the install; `tlc harness install` materialises
   the runtime.
2. **The contributor route is `tlc harness install --link`**, which points the runtime home at a checkout.
   Reachable from a fresh clone as `node bin/tlc.mjs harness install --link`.
3. **One wiring function**, called by `install` and by `update` on every platform. The win32 branch that shelled
   out to PowerShell is gone.
4. **No platform branch in the install path.** One link type (`"junction"`, which Node ignores off Windows), one
   hook command (`node`), one executable-extension list, one npm spawn.
5. **The launcher on PATH is npm's**, generated for the platform it runs on. The harness stops linking it.
6. **`bin/tlc-build` becomes `bin/tlc-build.mjs`**, and `bin/tlc-exec`/`bin/tlc-exec.cmd` are deleted — everything
   internal spawns the `.mjs` with `process.execPath`.
7. **`dist/` is no longer committed.** `prepack` builds it into the tarball; `check-dist-fresh` is deleted with it.
8. **Bun is the only bundler.** The esbuild fallback produced different bytes for the same source.
9. **Uninstall names every layout any version ever wrote**, with no platform to ask.

## Why

**The PowerShell installer was a second implementation of a defect the CLI had already fixed.** `install.ps1:73`
linked the init skill to `%USERPROFILE%\.tlc\skills\harness-init`. No provider reads that directory —
[/decisions/ad-095.md](/decisions/ad-095.md) established that each reads only its own — and `runUpdate` delegated
to that script on win32. So on Windows every `update` refreshed a skill nothing could route to, silently, using
the exact code the fix had replaced everywhere else.

**Every remaining platform branch was an artefact of shelling out.** The wiring was split because it called
`ln -sfn` on POSIX and PowerShell on Windows. Node needs neither:

- `symlinkSync`'s link type is only read on Windows and ignored elsewhere, so `"junction"` is one call that is a
  junction there and a symlink here — measured on Linux, and stated in Node's own API history. A junction also
  needs no Developer Mode, which the PowerShell installer demanded of a contributor.
- The hook command was `cmd /c node <launcher>` on Windows for Cursor and plain `node` for the other provider, on
  every platform including Windows. Two forms for the same mechanism, one of them from the first commit with no
  recorded reason; the branch was the odd one, not the safe one.
- `bunExecutableName` and the PATHEXT lookup chose a filename by platform. Asking for every name costs one
  `existsSync` per candidate and finds the same file.
- `npmSpawnOptions` set `shell` only on Windows, where `npm` is `npm.cmd`. The branch that mattered was the one no
  contributor here could run.

**A branch nobody can execute is worse than no branch.** Three of these were only reachable on Windows, and
`docs/decisions/ad-006.md` records that Windows behaviour inside an editor session is outside CI coverage. The
tests asserted the branch by overwriting `process.platform`, which tests the conditional and not the syscall.

**`bin/tlc-exec` was a bash file that `spawnSync` named on every platform.** `execBinPath()` returned it, so
`doctor`, `prices refresh`, `install-runtime` and `price-lookup` each spawned a file Windows cannot execute. The
hooks never had this problem because they name `tlc-exec.mjs` — the same launcher, spelled the way that works.

**`dist/` was tracked because of the installer.** [/decisions/ad-012.md](/decisions/ad-012.md) says it in one
line: "`dist/` stays tracked (the installer is `git clone` with no build step)". That installer is what this
record deletes, so the reason goes with it. `prepack` builds the bundles at pack time, which is also the only way
the published tarball can be built from the commit it claims. It removes a gate step, a CI step, and about a
megabyte of diff from every commit that touches `src/`.

**One bundler, because the artefact is bytes.** The bash build preferred Bun and fell back to esbuild, and the two
produce different output for the same source — 223,390 against 228,018 for one bundle
([/decisions/ad-046.md](/decisions/ad-046.md)). With `dist/` committed that made `check-dist-fresh` red for anyone
without Bun; without it, it would make two publishes of the same commit differ.

## Trade-offs

**`bin/tlc` and `bin/tlc.cmd` stay, and serve nobody new.** `~/.local/bin/tlc` on machines installed before the
package points at `bin/tlc`; deleting it kills their `tlc` command with no message. They go once those installs
have moved, which for an npm install is the next `update` and for a contributor is `npm link`.

**A managed git checkout without Bun can no longer be updated into a working state.** It has no committed bundles
to fall back on and nothing to build them with. `doctor` reports the missing bundles and names the build; the
supported route is the package.

**`npm link` and `npm i -g` own the PATH entry, so a broken PATH is now npm's error message rather than ours.**
`doctor` compensates: the "CLI on PATH" row resolves `tlc` through `PATH` and names the install command when it
finds nothing.

**A shell runs on every `npm` spawn, including POSIX.** The argv is fixed in our own files and the only
interpolated value is a directory this repository owns, so there is nothing for a shell to reinterpret.

**The Cursor hook command is now untested on Windows in a real session.** It was untested before too — the branch
existed, the coverage did not. If a Windows session proves `cmd /c` was load-bearing, `cursorWiring` is one line.

## Measured

`zizmor` on the three workflows: 0 high, 0 medium — the one medium was the release checkout keeping its App token,
now suppressed on that line with the reason, so a new checkout that forgets `persist-credentials: false` is still
reported.

The Node build produces bundles byte-identical to the bash one it replaces, checked with `diff -rq` against a copy
of the previous `dist/`.

`update` end to end on a linked contributor install: skills linked per provider, hooks unchanged, prices skipped as
fresh, doctor green including the corrected PATH row.

## Not decided here

- **Retiring `bin/tlc` and `bin/tlc.cmd`.** Stated above with the condition.
- **The `cmd /c` question on Windows.** One line, and no way to answer it here.
- **Whether `src/` should still ship alongside `dist/`.** It is what makes the Bun fast path resolve from source
  ([/decisions/ad-012.md](/decisions/ad-012.md)); the tarball carries both and the trade is unexamined.
- **A managed checkout route at all.** `update` still moves one to upstream. Whether that route should exist now
  that the package does is a separate decision with existing installs on the other side of it.
