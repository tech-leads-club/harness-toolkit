# AD-145 — a session's last real shell cwd is recalled wherever the host reports none

- **status**: active

## Decision

1. **`HandoffProviderSlice` gains `last_shell_cwd?: string`** (`src/core/handoff/handoff.types.ts`), written
   only from a `shell.before` event's own `event.cwd`.
2. **`tool-before.ts`'s `toolBeforeHandler` records it unconditionally, before the floor**, so it is captured
   regardless of what the command itself is later allowed to do. It is a no-op once the stored value already
   matches, so a session sitting in one directory pays this once, not on every command.
3. **`shaScopeRoot` (`support.ts`) becomes async.** It still prefers `event.cwd`; absent, it reads this
   session's own handoff slice and recalls `last_shell_cwd` through a new `recallSessionCwd`, which trusts the
   recalled path only when it still exists on disk and its `git rev-parse --git-common-dir` — a new
   `gitCommonDirOf` (`platform/git.ts`) — matches `projectDir`'s own. A mismatch, a missing path, or nothing
   recorded all fall back to `event.projectDir`, unchanged from before this record.
4. **`runLockedGate` (`stop.ts`) now hashes and executes against `args.shaRoot`, not `args.root`.** `root`
   stays the key for state — the gate lock, the cached artifact, lesson credit — exactly as AD-114 already
   split those from the files a turn actually changed.
5. **Every existing caller of `shaScopeRoot` gains an `await`**: `stop.ts`, `ship-gate.ts`,
   `prompt-submit.ts`, `tool-before.ts`'s two call sites, and `support.ts`'s own `observeForRules`. None of
   them change behaviour when `event.cwd` is already present, which is every case except Cursor's `stop` and
   `subagentStop`.

## Why

**Confirmed against Cursor's own documented hook payloads**, not assumed: `stop` carries `conversation_id`,
`workspace_roots`, `status`, `loop_count` and no `cwd`; `beforeShellExecution` carries `cwd` in addition to
the same base fields. `cursor.inbound.ts` already reflected this precisely — `event.cwd` is populated only
on `shell.before` — which is the same finding [/decisions/ad-114.md](/decisions/ad-114.md) and
[/decisions/ad-129.md](/decisions/ad-129.md) already made and left as a residual, undecided gap for `stop`
specifically.

**Reported live**: two Cursor conversations open in one window, one of them told mid-conversation to move
its work into a separate `git worktree`. The other conversation — an unrelated task — received a follow-up
message at its own `stop` naming ESLint/npm-cache files from the first conversation's own dependency
upgrade. `workspace_roots` is the IDE window's own open folders, identical for every conversation inside it;
a conversation navigating into a worktree via its own shell commands changes nothing the host reports at
`stop`, so `event.projectDir` stayed the shared window root for both. `runLockedGate`'s command execution
and its `computeInputsHash` both read `args.root` — the same shared value — so the grind gate for the second
conversation ran `git diff`/lint against the first conversation's own working tree, and reported its
failure as the second conversation's own.

**A cwd-bearing event from the same session is evidence; `workspace_roots` is not.** `beforeShellExecution`'s
`cwd` is the one field this project has already measured as trustworthy for Cursor
([/decisions/ad-141.md](/decisions/ad-141.md) — truthy, not merely present). Recalling it for a later event
of the same session is not inventing a value the host never reports; AD-129's own "Not decided here" ruled
out inventing a `cwd` source for an event kind that never carries one at all, which recall does not do — it
reuses one this exact session already reported through a different event kind.

**The recall is validated, not merely stored.** A worktree can be removed between the shell command and the
`stop` that follows it, and a stale slice inherited from a dead predecessor session
([/decisions/ad-122.md](/decisions/ad-122.md)) could in principle still name a path. `gitCommonDirOf` — every
worktree of one repository shares this path, unlike `gitRootOf`'s own toplevel — is what tells "a worktree of
this same repository" apart from "an unrelated directory that happens to exist."

## Trade-offs

**One extra `git rev-parse --git-common-dir` per side, paid only on the path this record actually changes.**
`recallSessionCwd` returns early, with no git call at all, when nothing was recalled or the recalled path
already equals `projectDir` — the common case for a session that never left its own workspace root.

**`runLockedGate`'s gate lock still coordinates by `root`, not `shaRoot`.** Two sessions in genuinely
different worktrees of the same repository still serialize against each other's grind gate rather than
running concurrently, exactly as they did before this record. They are not racing over the same physical
files, so this is a wasted wait, not a correctness gap — narrowing the lock's own key is a separate,
unrequired change this record does not make.

**A session that never ran a shell command before its first `stop` still resolves to the shared workspace
root.** There is nothing to recall yet — the same answer the harness has always given for that case, not a
regression this record introduces.

## Not decided here

- **Narrowing `runLockedGate`'s gate lock to `shaRoot`.** Named above as a real, separate improvement — two
  worktrees of one repository do not actually contend for the same files, but they still wait on each
  other's gate today.
- **A `cwd` source for Cursor's `beforeSubmitPrompt` or `subagentStop`.** `subagentStop` gains the same
  recall as `stop` for free, through the same `shaScopeRoot`; `beforeSubmitPrompt`'s own `turn_base_sha`
  capture ([/decisions/ad-144.md](/decisions/ad-144.md)) is a separate value with a separate recorded root,
  not touched here.
