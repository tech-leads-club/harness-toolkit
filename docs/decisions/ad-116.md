# AD-116 — `push` and `gh pr create` run the stop-time battery before shipping, identically on every provider

- **status**: active

## Decision

1. **`push`/`pr-open` run the full stop-time battery before the command executes**: comments
   ([/decisions/ad-115.md](/decisions/ad-115.md)), lint, test, docs (only when
   `policy.docs.severity === "deny"`), duplication, and any `on: stop` operator rule. `commit` keeps
   only the cheap comment check — measured in this repo, lint+test run ~9.4s cold, and paying that
   on every local, reversible commit inside a turn is the edit-time cost AD-111 already declined,
   moved to a higher frequency.
2. **`src/entrypoints/support.ts` gains `computeTurnScope`**, the one answer to "what did this turn
   add" (`turn_base_sha`, changed files, code/test/comment targets). `stop.ts`'s own inline version is
   left as-is — its `handoff` read serves many other fields this function does not return, and
   refactoring that under this change's scope was a larger, riskier edit than the residual
   duplication it would remove. Recorded here rather than silently duplicated.
3. **`stop.ts` exports `runLockedGate` and `GateRun`** — no second gate runner. The new
   `src/entrypoints/ship-gate.ts` calls the same lock, the same content-hash cache, the same
   observability as `stop.ts`'s own lint/test/docs.
4. **A hard block on `Edit`/`Write` in `tool.before`, content-checked before the write lands, is
   declined** (see Why). The edit-time advisory ([/decisions/ad-111.md](/decisions/ad-111.md)) and
   the ship-time gate remain the enforcement points.

## Why

**Verified live, not assumed.** Multiple `anthropics/claude-code` issues across 2026 report
`PreToolUse` `permissionDecision: "deny"` being ignored specifically for `Edit`/`Write` (the tool
executes anyway) while reliably blocking `Bash`. Tested directly in this session on the installed
CLI (2.1.247): both an `Edit` and a `Write` denied by the harness's own floor were correctly
refused — the files were never touched. So the mechanism is not unconditionally broken here, but it
is a documented, recurring class of host bug specifically for `Edit`/`Write`, on top of Cursor's own
`preToolUse`-before-write payload shape being undocumented for whether it carries proposed content
at all. Given an explicit requirement that behavior be identical on both providers, building on a
mechanism that cannot be verified symmetric is the wrong trade — `shell.before` (`Bash`) is the
confirmed-reliable, confirmed-symmetric block point, so that is where enforcement lives.

**The vocabulary and the cache already existed.** `commit`/`push`/`pr-open` are the same closed
shape family AD-115 already matches. `runLockedGate`'s content-hash cache means running the battery
at ship-time does not double the cost of a turn that also stops normally — the second, stop-time
pass is a cache hit on unchanged files.

## Trade-offs

**`stop.ts`'s turn-scope computation and `computeTurnScope` are not unified.** Two answers to "what
did this turn add" now exist in the codebase, which is exactly the drift
[/decisions/ad-071.md](/decisions/ad-071.md) warns about. Accepted here because `stop.ts`'s local
`handoff` read also serves fields (`blockers`, `previous_gaps`, `plan_*`, `last_ship_claim_*`,
`last_fingerprint`, …) that `computeTurnScope` does not return, and consolidating those under this
change's scope risked a much larger, harder-to-verify diff than the specific defect being fixed.
Flagged under "Not decided here" rather than silently left.

**A turn that pushes more than once pays the battery more than once**, though every pass after the
first is a cache hit unless files changed in between. Same shape `stop.ts` already tolerates within
one turn's own retries.

**`gh pr create --dry-run` and similar non-shipping invocations of the same commands are still
gated.** The trigger matches on shape (`gh pr create`), not on whether the invocation actually
publishes anything — same limitation `review-before-pr`'s `pr-open` trigger already has.

## Not decided here

- **Unifying `stop.ts`'s inline turn-scope computation with `computeTurnScope`.** See Trade-offs.
- **The `Edit`/`Write` hard block, if the host bug is ever confirmed fixed on every supported
  provider.** `shaScopeRoot`-style parity checking would need to be repeated per host capability,
  not assumed.
- **Distinguishing `gh pr create --dry-run` from a real one.** Not reported, not evidenced.
