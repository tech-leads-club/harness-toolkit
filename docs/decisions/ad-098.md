# AD-098 — Splitting is reverted: a shared chunk ran the CLI's main

- **status**: active

## Decision

1. **One bundle per entrypoint.** Splitting reverted.
2. **Splitting returns only when no library module carries `import.meta.main`** — the invocation has to move to
   thin entries nothing imports.
3. **A bundle is checked by what it does.** Exactly one may answer as the CLI.
4. **`update` on an npm install materialises from the package it just installed**, through the package's own
   launcher, with `TLC_ORIGIN` and `TLC_INSTALL_DEST` both named.
5. **`perf` earns a patch.**

## Why

**Splitting broke three commands.** A shared chunk carries the module body of anything two entries import.
`bin/tlc-cli.ts` is imported by `install-runtime`, `doctor` and `lessons-cli`, and its `if (import.meta.main)`
guard evaluates true inside the chunk — so those entries ran the CLI's `main`. On the published 0.3.2,
`tlc harness install` prints `unknown:` and installs nothing.

**The old check could not see it.** It asserted each bundle imports without throwing. A bundle that runs somebody
else's program imports fine. The replacement executes each one and fails when a non-CLI bundle answers as the CLI.

**The size it bought:** 5.0 MB → 548 KB, tarball 1.6 MB → 426 kB, and 41 ms → 37 ms per hook (40 runs,
interleaved). Not worth a CLI that cannot install.

**`update` never delivered code to an npm install.** The npm branch bumped the package, then spawned
`install-runtime` through the *runtime home's* launcher — source and destination resolved to the same directory,
"nothing to copy". Measured: package 0.3.0 → 0.3.2, runtime stayed on 0.3.0. Predates the installer removal, and
`doctor` claimed update "re-materialises this directory" the whole time.

**`perf` releasing nothing had a cost.** The build change computed `bump=none` and would have waited for an
unrelated `fix`. `chore` and the inert scopes are what stop the release loop, not this.

## Two more, found while checking the size

**`--minify` instead of splitting.** 40% of the same waste with no change to module identity: `dist/` 5.0 MB →
3.0 MB, `stop.mjs` 281,400 → 164,937 bytes, tarball 1.6 MB → 1.3 MB. Safe because nothing in this repository
reads a function or class name at runtime and no stack trace reaches an operator — both checked before turning it
on. The remaining 60% still needs the refactor in decision 5.

**`prices lookup` dropped its provider.** The tool parsed `[provider]`, the CLI route discarded it, so every
lookup ran with an empty provider — the one value that matches no provider plane. `prices lookup composer-2.5
cursor` answered `source: missing` for a model priced `$0.5/$2.5`, while the same call straight to the tool
resolved it. The help and `docs/measure.md` had documented the argument all along. Found by exercising the
commands on a minified install rather than by reading the diff.

## Trade-offs

- `dist/` stays 5.0 MB and the tarball 1.6 MB.
- The condition in decision 2 is a refactor across `bin/tlc-cli.ts`, `bin/tlc-exec.mjs` and every `tools/*.ts`
  with a guard.
- The new rail runs 24 processes, about two seconds.
- **0.3.2 is broken and published.** Deprecated on the registry pointing at the fix, not unpublished: a version
  somebody pinned disappearing is worse than one that warns.

## Not decided here

- **Replacing `import.meta.main` with an argv comparison.** In a chunk it compares against the chunk's URL, so the
  CLI would fail to run when it *is* the program. The fix is structural.
- **Unpublishing 0.3.2.** Allowed within 72 hours; deprecation chosen.
