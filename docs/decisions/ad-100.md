# AD-100 — The operator declares the trigger and the proof; the harness enforces it

- **status**: active

## Decision

1. **A rule is one markdown file**: frontmatter the harness enforces, body the operator writes and the harness
   injects verbatim when the rule fires.
2. **Two tiers, unioned.** The runtime home's rules apply in every repository; the project's apply in that one.
   Deduplicated by file name with the project winning, and a project rule carrying `enabled: false` switches a
   global one off there with its body as the reason. This is the lesson tier model, not a second convention
   ([/decisions/ad-040.md](/decisions/ad-040.md)).
3. **Closed vocabularies.** Triggers: `pr-open`, `commit`, `push`, `stop`, `tool(<name>)`, `command(<pattern>)`.
   Proofs: `subagent(<type>)`, `command(<pattern>)`, `gate(<name>)`, `file(<glob>)`, each `since HEAD` unless the
   rule says `since session`. Anything outside either is a named parse error.
4. **A proof is only something the harness observed.** Never the agent's assertion, never a model's verdict.
5. **Four verdicts**, and posture reaches exactly one: `ask` interrupts under `paired` and hardens to `deny` under
   `solo` and `focus`. `deny`, `follow-up` and `warn` are identical at all three postures.
6. **Off by default**, and inert with no rule files.

## Why

**An instruction is not a guarantee, and this repository already had the instruction half.** A pinned global
lesson reaches the model — measured: `session-start.ts` injects the selected block, `lesson.select.ts` puts pinned
ones ahead of everything scored, and the transport differs by host because one of them does not deliver context
returned from its session-start hook. What it cannot do is guarantee the model acted on it. Enforcement needs a
gate, and a gate needs a fact.

**Which is why the gate rests on existence, not on a verdict.** "The jury approved" is an opinion that varies
between runs; "a reviewer ran over exactly this code" is a fact. That distinction is also the industry's:
deterministic checks are what merge gates are made of, and agentic review is a hypothesis generator.

**And the fact has to be one the agent cannot manufacture.** The observation store is under the project state
directory, which the floor's `policy-surface-write` refuses to an agent through a shell redirect, an interpreter
or a write tool ([/decisions/ad-022.md](/decisions/ad-022.md)), and the mutating `tlc harness` subcommands are
refused from inside a session. So the only writer is the harness reacting to a host event. That property is
inherited, not built.

**No exit code exists, and none is needed.** Measured on 3,755 real `shell.after` records in this repository's
own audit log: the payload carries `tool_response: {stdout, stderr, interrupted, …}` and no exit code, in any of
the three shapes the two hosts send. But a tool that fails arrives as `tool.failure` — 64 of those in the same
file, one a `Bash` that exited non-zero. So observing at `tool.after` already means the command ran and did not
fail. 65 of those records carry a non-empty stderr, so stderr is not failure either.

**Freshness is part of the proof.** A review of the code as it was two commits ago reviewed something else, so an
observation carries the HEAD it was made against. A project with no git checkout cannot satisfy `since HEAD` at
all — treating "no sha" as "any sha" would make every such rule satisfiable by anything.

**Posture may not touch verification.** `deny`, `follow-up` and `warn` are the evidence bar, and a posture that
switched one off is the defect the posture feature exists to remove ([/decisions/ad-025.md](/decisions/ad-025.md)
item 4). `ask` is an interruption, which is the one thing posture governs — and it hardens rather than softens,
the same direction it already degrades in on a host that cannot ask.

**One frontmatter reader.** There were two: a full parser in `tools/dev`, which never ships and which `core/` may
not import, and a private single-field extractor in `core/release`. This feature needed a third caller, so the
parser moved to `platform/` — a format primitive with no policy in it, and the one direction all three callers may
import from. The two existing callers' 54 tests pass unchanged.

**One shell splitter.** A trigger cannot be a substring test: `x && gh pr create` opens a pull request and a
heredoc body mentioning the same words is a document. `tokenizeShell` already answers both, and a second regex
here would be the copy that goes wrong later.

## Trade-offs

**The quality of a review is not enforceable.** The gate proves a reviewer ran over this code. Whether the review
was any good is outside what a deterministic check can say, and pretending otherwise would be the probabilistic
enforcement this decision refuses.

**A pattern trigger is policy, not containment.** A script written to disk and executed later, a command name
built at runtime, `gh api` instead of `gh pr create`, a pull request opened in a browser — all escape it. The rule
covers the agent's shell path, and the capability's trade-off says so.

**Adding a trigger or a proof touches two places** — the union and its evaluator. That is deliberate: with an
exhaustive switch the compiler refuses to build until the new kind is handled everywhere, while a handler registry
would let a forgotten evaluator compile into a proof that never holds. Open/closed pays off for third-party
plugins; here the vocabulary is closed by decision.

**`file(<glob>)` is three shapes, not a glob engine** — an exact path, `*.ext`, or a `dir/` prefix. Nothing else
in this repository needs globs, and an engine written for one caller is generality nobody asked for.

**A rule fires per tool call, so it reads its directories per tool call.** With none declared that is two
`existsSync` calls; the sha, which is a process spawn, is asked for only after a rule has already fired.

## Measured while building it

Four mutations that killed tests, and two that did not and were the useful ones:

- union turned into override → 3 tests fail; an unknown proof made silent → 1; the tokenizer replaced by a
  substring → 2; `ask` softening instead of hardening → 3; the most permissive outcome deciding → 1;
  `tool.failure` counting as proof → 1; the rail's verdict ignored → 3; `rules.enabled` ignored → 1.
- A mutation that removed a `splitHeredocs` call **survived**, which exposed the call as dead rather than
  untested: `tokenizeShell` already declines to emit segments from a heredoc body. Measured both ways, identical
  output.
- The first end-to-end fixtures put the command in `tool_input.command` on a Cursor payload and invented a session
  key with a colon. Both made every assertion pass by allowing. The real shapes — Claude sends
  `tool_input.command` on a `PreToolUse` whose tool is Bash, Cursor sends a top-level `command` on
  `beforeShellExecution`, and the key is `cursor-conv-1` — came from the provider code and from the audit log.
- The capability switch was read in **three** places: the service, the entrypoint rail, and `doctor`. Two were
  dead — mutating either to `false` changed nothing, because the service already answered. The switch now has one
  owner, and mutating it fails 7 tests.

### The feature shipped with no producer

Worse than the one above, and the same shape twice:

1. **`observe` had no caller.** It was exported, wired into the facade, and called by nothing. The store was never
   written, so no proof could ever exist, so every rule that parsed denied for ever — and `require:` is mandatory,
   so that was every rule. 113 tests passed, because each one wrote `rule-observations.jsonl` itself. A consumer
   verified against a hand-written store cannot see a missing producer. The end-to-end run that appeared to show
   the loop closing was a script calling `observe` by hand, which supplied the missing half and hid it.
2. **And the field it read was the wrong one.** On `subagent.stop` both hosts carry the type in
   `spawnSubagentType`; `subagentType` is what a *spawn* carries. Measured by running a real payload of each of
   five shapes through the providers. So even once wired, a subagent would have recorded nothing — and the unit
   test passed because its fixture invented the field name it was asserting about.

Neither was findable from the consumer side. What finds them is a test that closes the loop through the real
rails and writes nothing itself: `rules.loop.test.ts` drives `subagent.stop`, `shell.after` and the stop gate as
producers and `shell.before` as the consumer. Turning off any one producer kills it — measured at 4, 1 and 1
failures; the wrong field, 4; a failed gate counting as proof, 1; recording a kind no rule asked for, 1.

The gate proof is recorded at the single point every gate already funnels through, on the same argument
`recordGateOutcome` makes for itself: a gate added later cannot be forgotten. Only a gate that **passed**, because
"the gate ran" must not satisfy a rule that asked whether it passed.

`wants` is asked before the sha is fetched: the observing rails fire on every tool call and the sha is a process
spawn, so an operator whose only rule wants `subagent(the-jury)` pays two directory reads per command and no git.

### The gate deleted this repository's `bin/`

Found by reading the gate's own output rather than its exit code, and worth recording because the cause was a
production defect and only the test harness made it visible:

1. `tlc harness test` runs each step as a child, so every step inherited `TLC_ORIGIN=<repo>` and
   `TLC_HOME_FROM_ENV=0` from the CLI.
2. `tools/test-env.mjs` scrubbed the variables that name **which project** and redirected `TLC_HOME`, but not
   these two. `installDest` honours `TLC_HOME` only when `TLC_HOME_FROM_ENV` says an operator chose it, so a
   spawned bundle resolved the conventional home — `~/.tlc/harness`.
3. On a machine installed with `--link`, that path *is* a symlink to the checkout.
4. `installRuntime` guarded against copying a directory onto itself with `resolve(source) === resolve(dest)`, and
   `resolve` does not follow a symlink. The two paths differed lexically while naming one directory.
5. `rmSync` followed the link and deleted `<repo>/bin`, then `cpSync` failed on the source it had just removed.
   Four suites then failed for want of a launcher, which is the only reason anyone looked.

The guard now compares real paths, the suite scrubs both names and redirects the install destination, and each has
a rail that dies when reverted (1 failure and 2 respectively). Reachable without any of this repository's tests:
any operator who installed with `--link` and then ran `tlc harness install` lost their checkout's `bin/`, `dist/`,
`docs/`, `skills/`, `src/` and `tools/`.

## Not decided here

- **A `checks(green)` proof.** It would need the harness to run a network command; today an operator writes
  `command(gh pr checks)` and the proof is that it ran and did not fail.
- **Boolean algebra.** `require` is a conjunction. Anything richer is a language, and a language needs a reason.
- **The harness running the reviewer.** It answers hooks with decisions and text; it does not spawn agents.
- **Whether `stop` rules should also block.** The `follow-up` verdict is declared and parsed, and the stop rail
  that acts on it is not in this change.
