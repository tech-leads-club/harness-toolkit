# AD-109 — A lesson's credit is graded by the session that earned it, not by whichever session runs the gate next

- **status**: active

## Decision

1. **`PendingLessonCredit` gains an optional `sessionKey`.** Optional so an on-disk record written
   before this field existed still credits once — the same legacy fallback
   [/decisions/ad-038.md](/decisions/ad-038.md) used for pre-existing lesson records.
2. **The write site (`failGate`) stamps the injecting session's key.** The read site
   (`creditPendingLessons`) now returns without crediting — and without clearing the field — when
   `pending.sessionKey` is set and does not match the session about to credit it.
3. **A mismatch is a no-op, not a transfer.** The credit is left for the originating session to consume
   if it ever runs the gate again; if it does not, that one observation is lost rather than mis-recorded.

## Why

**The same per-project handoff, the same missing session check, a different field.** AD-107 fixed
`blockers` leaking across subagents sharing a project handoff and asked, in its own reasoning, whether
the same shape existed elsewhere. An independent audit run against that exact question found it:
`creditPendingLessons` in `stop.ts` compared `pending.gate !== args.gate` and nothing else — no session
identity anywhere in the check, though `readHandoff`/`patchHandoff` are keyed on `root + provider`, not
on session. Reproduced: session A fails `lint`, a lesson is injected and `pending_lesson_credit` is
written with no session marker; session A ends without running `lint` again; session B — a different
`session_id`, same project and provider — runs later, passes `lint` for reasons of its own, and
`creditLessons` marks the lesson `helped` even though session B never received its text.

**The corruption is silent by construction.** `helpedCount`/`neutralCount` feed
`lessonEffectiveness`, the number `tlc harness lessons list` and `doctor` show an operator deciding
whether a lesson earns its place. A false `helped` looks identical to a true one; nothing errors, and
nothing in a green test suite caught it — the existing test file always drove every stop through the
same `session_id`, so the cross-session path had zero coverage.

**A no-op, not a reassignment, on mismatch.** The alternative — crediting whichever session is present
when the gate next passes — is the bug. Silently dropping the observation loses one data point for a
lesson that may never get graded if its originating session never returns; that is a smaller cost than
recording help a lesson never gave, given the field's whole purpose is deciding whether to keep trusting
it.

## Trade-offs

**A lesson whose originating session ends without re-running the gate is never graded.** Before this
fix it was graded — incorrectly, by an unrelated session. After, it is not graded at all. Silence is the
correct trade against a false positive here: `lessonEffectiveness` already treats no observation as
`unproven`, which is an honest answer this field did not previously give.

**The legacy fallback re-opens the same hole for any record already on disk.** A `pending_lesson_credit`
written before this shipped has no `sessionKey` and will credit exactly as it did before, once. Accepted
for the same reason AD-038 accepted it: punishing an existing store for a field that did not exist when
it was written is a worse default.

## Not decided here

- **Whether the no-op case should be surfaced to the operator** (e.g., an obs record noting a dropped
  credit). No case has asked for this observability yet.
- **A session-scoped handoff more generally.** This is the second field patched onto the same
  per-project file rather than the file being restructured; AD-107 already named that larger change as
  future work, not this record's.
