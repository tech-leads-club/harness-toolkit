# AD-143 — a session with no usage source reads as unavailable, not as `$0.0000`

- **status**: active

## Decision

1. **`SessionRollup` (`src/core/observability/observability.store.ts`) gains `usage_reported:
   boolean`**, defaulting to `false` in `newRollup()`.
2. **`updateRollup` (`src/core/observability/observability.service.ts`) sets it to `true` the first
   time an event's `gen_ai` field is present at all** — before the existing token-value check, so a
   reading of exactly `{input_tokens: 0, output_tokens: 0}` (rare, but not impossible) still counts
   as "a real reading arrived," distinct from "no reading ever arrived."
3. **A shared `costLabel()` helper (`src/core/observability/observability.report.ts`) replaces two
   near-identical inline computations** in `sessionReportMarkdown` and `sessionReportScreen`. When
   `usage_reported` is `false` it returns `"not available (this host reports no usage data)"`;
   otherwise it falls through to the existing `cost_incomplete` handling, unchanged.
4. **New tests** in `observability.report.test.ts` cover both the new "unavailable" case and confirm
   the pre-existing "incomplete" case still requires `usage_reported: true` to reach it — the two
   are different reasons a cost number is not a plain answer, and a session must be in the first one
   before the second is ever checked.

## Why

**A direct question, asked live.** After AD-142 shipped, the operator asked: since Cursor's cost
line will keep reading `$0.0000` forever, how does an operator reading that number tell "confirmed
zero" from "the harness has no idea"? It could not — `estimated_cost_usd` starts at `0` in
`newRollup()` and nothing changed it either way for a provider with no usage source, so a session
that got real `{cost_usd: 0}` readings and a session that never got a single reading were
indistinguishable in the rendered report. `cost_incomplete` already exists for a *different* kind of
incompleteness (a reading arrived, its model had no catalog rate) — this is a *third* state
(`AD-142`'s own Trade-offs section named it and deferred it), not a variant of that one.

**A boolean on arrival, not on value.** `usage_reported` is set by the mere presence of `event.gen_ai`,
not by whether its tokens are non-zero — so a provider whose usage genuinely nets to zero (a fully
cached, free response, say) is still told apart from a provider that never reports usage at all. The
distinction the operator asked for is exactly "did anything ever arrive," which is what this
tracks.

## Trade-offs

**This does not add usage data for Cursor.** It only stops a missing answer from looking like a
computed one. Cursor's line reads "not available" now instead of `$0.0000` — the underlying gap
AD-142 already documented (no confirmed source) is unchanged.

## Not decided here

- Everything AD-142's own "Not decided here" already listed (the Admin API's Enterprise-Teams
  gating, `afterAgentResponse`'s unconfirmed payload shape) is unaffected by this record.
