# AD-096 — Prices are the machine's, in one file, and the parser that fills it was wrong twice

- **status**: active

## Decision

1. **No price is versioned or packaged.** `model-prices.cursor.json`, `model-prices.json` and
   `model-aliases.json` are removed from the repository and from `files`.
2. **One catalogue per machine**, `<runtime home>/model-prices.json`, with `planes` keyed by billing origin —
   a provider's id for what that provider charges, `litellm` for vendor list prices.
3. **The planes are not merged.** The same model has one rate from its vendor and another from a provider
   reselling it.
4. **Overrides are `model-prices.local.json`** and win over every plane. A legacy flat `model-prices.json` is
   moved there rather than overwritten.
5. **The alias table is code**, `MODEL_ALIASES` in `src/platform/pricing.ts`, not a data file.
6. **One key function**, `slugifyModelName`, used by the refresh that writes and the lookup that reads.
7. **`install` fetches once; `update` refreshes past a 7-day TTL; `doctor` reports the age.** A failed fetch never
   fails an install or an update.
8. **A plane is replaced only if it keeps at least half of what is on disk**, and a refused plane leaves every
   other plane and every date untouched.

## Why

**A rate in a commit reaches an operator only through a release.** The catalogue in this repository was written
2026-07-27 and was still being packed on 2026-08-19, through three published versions — 23 days stale, with the
staleness recorded in `_meta.refreshedAt` and read by nothing.

**Two of the three versioned files were not data anyone maintained.** `model-prices.json` was `{}`. Of the ten
entries in `model-aliases.json`, six were `"x": "x"` and two more were already covered by the effort suffix the
lookup strips; two were load-bearing.

**The parser read one table of three.** It `break`s on the first line that is not a table row, which was correct
when the upstream page carried a single table. The page now carries three. Measured: 43 models became 3, and the
only guard was `count === 0` — so a mutilated catalogue overwrote a good one and printed a success line. That is
what turned "stop versioning prices" into "the refresh cannot be trusted to be automatic".

**The key function erased the qualifier.** It dropped anything in parentheses, so `Composer 2.5` and
`Composer 2.5 (Fast)` collapsed onto one key and the second silently won. Measured on the real page: 51 model rows
became 44 stored keys, and every model with a Fast variant reported the variant's price — `$3/$15` where the page
says `$0.5/$2.5`, `$4/$12` for a model priced `$2/$6`. Roughly double, for as long as the catalogue has existed.

**There were two of those functions and they disagreed.** The writer's copy and the reader's copy both erased
parentheses, in slightly different ways. A catalogue is only correct if the key written is the key asked for, so
there is now one function and a test that asserts every stored key equals what the reader computes for the same
name.

**Neither defect was testable.** The file fetched at module scope, so importing it to test the parsers would have
reached the network — which is why a parser holding two wrong answers had no tests at all. The fetches moved into
`main()` behind `import.meta.main`, the pure functions are exported, and both defects now have a test that fails
without the fix.

**The docs claimed a check that did not exist.** `docs/measure.md` said `doctor` "requires at least one provider
catalog to be present". No such check existed, and an absent catalogue is invisible: cost estimates come back
`null`, which reads exactly like a turn that spent nothing.

**The read path parsed every catalogue on every lookup.** The vendor plane is about a megabyte and a cost estimate
runs on every tool result. It is now cached on the file's mtime and size, so a refresh mid-session is picked up on
the next lookup without an invalidation call.

## Trade-offs

**A fresh install has no prices until something fetches them.** `install` does, and tolerates failure; behind a
proxy or offline the harness works and reports no costs until the next refresh. Before, a stale catalogue shipped
in the package and every install had *something* — wrong, but present.

**The catalogue is one file holding both planes, so a lookup parses the vendor plane too.** Bounded by the cache,
and it was already parsing all three files on every call.

**`retireSupersededFiles` deletes three named files from the runtime home.** Only those exact names, only there,
and only after a successful write — but it is a tool deleting files an operator can see.

**An operator who hand-edited `model-prices.json` gets it moved.** Named in the output, non-destructive, and it
happens once. Someone who has *both* that file and `model-prices.local.json` is told to merge them by hand.

**The TTL is one number for both planes.** A provider's pricing page changes more often than the vendor list; 7
days is a compromise, and `--if-stale` is per plane so the split can be made later without a schema change.

## Measured after the change

A first fetch on an empty runtime home: 47 models in the provider plane, 4745 in the vendor plane, one 1.1 MB
file. Of 3055 upstream vendor entries, 498 are skipped — every one of them lacking an input or output cost, which
is the documented rule; the plane is larger than the upstream key count because a slugged alias is stored beside
each id.

Resolution, read from the real catalogue: `composer-2.5` is `$0.5/$2.5` and `composer-2.5-fast` is `$3/$15`;
`grok-4.6` is `$2/$6` and `grok-4.6-fast` is `$4/$12`. Before the fix each of those pairs was one key holding the
variant's price.

**`auto` resolves to nothing, and that is upstream's shape.** The provider's page no longer carries an Auto Cost
row in a table — it states only that the rate "is set per million tokens" in prose. The alias is kept, so the row
returning restores the mapping; until then a turn on Auto reports `cost_usd: null` rather than a guess.

## Not decided here

- **Whether a second provider's own rates get a plane.** The shape allows it; nothing fetches one.
- **Where the pool inference belongs.** `inferPool` names vendors and lives in the tool, which is correct for the
  boundary and means the rule is not testable from `core/`.
- **The suffix-stripping fallback.** `model-x-fast` still falls back to `model-x` when the variant is not priced
  separately, which is a guess. The exact key wins first, and a wrong-by-a-fallback price is still a wrong price.
- **Two test files that read the operator's own `config.json`.** Fixed by sandboxing `TLC_HOME` in each, after both
  failed on this machine and passed in CI. Whether the gate should isolate the runtime home for the whole suite is
  a larger change than this record.
