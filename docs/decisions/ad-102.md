# AD-102 — A green gate is not a working product, so four checks that look where it cannot

- **status**: active

## Decision

1. **The suite gets a fake home.** `HOME`, `USERPROFILE`, `CLAUDE_CONFIG_DIR` and `CURSOR_CONFIG_DIR` are
   redirected into one throwaway directory, and the guard asserts the *resolver* — that `os.homedir()` answers the
   fake — not the variable.
2. **knip walks the module graph.** `--files --dependencies` blocks at zero; `--exports` blocks on growth past a
   ceiling written in code.
3. **The packed artefact is driven in a clean room** before `npm publish`, never after.
4. **A release publishes on merge, tokenless and unattended.** Trusted publishing mints a short-lived OIDC
   credential per run; the safety is the gate and the clean-room install, not a channel and not a gate-keeper. There
   is no rollback for a registry — the recovery is the next patch.

## Why

**Six defects reached a live machine in one day, every one with the gate green.** They are not six accidents; they
are four blind spots:

| defect | what it needed |
|---|---|
| a test deleted this repository's own `bin/` | a home the suite cannot escape |
| a wiring step pointed the operator's `tlc` at a temp directory | the same |
| `observe` was exported, wired into the facade, and called by nothing | something that walks the graph |
| 0.3.0 installed nothing; 0.4.0 left `tlc` off `PATH` | driving the published artefact |
| 0.4.2 shipped a defect 0.4.3 fixed minutes later | somewhere for a release to sit |
| a POSIX path assumption in a test | the Windows leg of CI — which already caught it |

The last row matters as much as the others: one of the six was already covered, and the check worked. The problem
was never "add more checks", it was that three specific things nothing looked at.

**A fake home closes a class instead of an instance.** The first three defects were patched one variable at a time,
each after it reached a machine — `TLC_HOME`, then `TLC_ORIGIN` and `TLC_HOME_FROM_ENV`, then `TLC_INSTALL_DEST`,
then `TLC_BIN_DIR`. Four paths derive from `homedir()` and none of them was redirected, so `wireRuntime` in a test
linked skills into the operator's own `~/.cursor` and merged their `settings.json`. Nothing had broken there yet
only because no test happened to step in it. The published pattern is to redirect the home in a session fixture and
assert on the resolver, so a name added to the list without the setup honouring it fails.

**Nothing here walked the module graph.** The existing checks look for a union member read and never written, a
suppression whose reason is not a reason, a screen that paints its own strings. All are shape checks on files.
`ts-prune` was archived in December 2023 and its author points at knip, which uses the same mark-and-sweep
algorithm over a full graph and additionally reports unused files and dependencies — things ts-prune could not see.

**The suite runs against the working tree, which is not the package.** Three install defects reached operators
through exactly that: 0.3.0 installed nothing, 0.3.2 shipped bundles where every entry answered as the CLI, 0.4.0
left the command off `PATH`. Packing, installing the tarball the way `npx` would, and driving the installed binary
is the only thing that speaks about the artefact.

**And a release wanted a window it turns out not to need.** 0.4.2 shipped a defect that 0.4.3 fixed minutes later,
and the instinct was to add somewhere for a release to sit. Two shapes were built and both were worse:

- **A `next` dist-tag with a promotion workflow.** This is how the npm CLI itself releases, and it is wrong *here*
  because promotion needs an automation token: trusted publishing covers `npm publish` and not `npm dist-tag`, and
  an open npm/cli issue asks for exactly that. It would have meant storing a long-lived credential in a repository
  that stores none — and a `next` version is installable anyway, merely unadvertised.
- **`npm stage publish`.** Tokenless, and genuinely not installable. But every stage subcommand except `publish`
  requires proof of presence, so **no workflow can finish a release** — which converts every merge into a manual
  2FA step and leaves versions queued with nothing able to remind anybody.

The answer is the one the ecosystem actually converged on in 2026, and this repository already had most of it:
publish on merge with trusted publishing, and make the *checks* the gate. Short-lived per-run credentials replaced
long-lived tokens across the ecosystem after the 2025–2026 supply-chain worms, and provenance comes from the same
identity for free.

**What replaced the window is evidence, not delay.** Eighteen gate steps on four platforms, and then the packed
tarball installed into a container and driven as a real command before anything is published. 0.4.2's defect was a
project-discovery bug that the clean-room install would not have caught — but the two before it, 0.3.0 installing
nothing and 0.4.0 leaving `tlc` off `PATH`, are exactly what it catches.

**And a registry has no rollback.** Versions are immutable and re-pointing `latest` needs a token, so "roll back"
means ship the next patch — which is what actually happened with 0.4.3, in minutes, with no ceremony.

## Trade-offs

**A fake home makes some tests unrepresentative, silently.** Two floor tests asserted that destroying a
home-relative path is denied, and went vacuous the moment the fake home moved into the OS temp directory — which
that rule treats as disposable on purpose. The rule was right for the input it was given. Those tests declare their
own home now, but the lesson generalises: a hermetic fixture can be *too* hermetic, and only reading the assertion
tells you.

**knip's coverage here is incomplete and I could not find out why.** A dead export added to
`src/platform/paths.ts` or `src/platform/links.ts` is not reported, while `style.ts`, `pricing.ts`,
`rules.proof.ts` and `rules.trigger.ts` all are. Five hypotheses tested — entry file, imported-by-an-entry,
imported-by-the-CLI, `export *` re-export, `--include-entry-exports` — none explains it. The ceiling mechanism does
work: 76 findings against a ceiling of 75 exits non-zero. So the step is real and its coverage is not complete, and
`CONTRIBUTING.md` says so in the row itself. A check trusted past its evidence is worse than no check.

**The exports ceiling is a debt, and a number can be raised.** It is in code rather than a snapshot file precisely
so raising it is an argument in a diff somebody reads.

**The clean room is weaker without docker.** It falls back to a throwaway npm prefix, which covers packaging and the
command's behaviour but shares the host filesystem. The output names which of the two ran.

**A bad version reaches everybody immediately.** That is the honest cost of publishing on merge, and it is bought
back with the gate rather than with delay. The mitigation is that the fix ships as fast as the defect did.

**Two settings outside this repository decide whether "tokenless" is true or only available.** *Require OIDC* on
npmjs.com disables token publishing for the package — without it a token still works and the property is optional;
npm's publish emails say `via OIDC` or `via token`, which is how to check. And required reviewers on the `publish`
environment decide whether releases are unattended. The environment must keep its name either way, because the
trusted publisher is registered against it. Neither is in the repository, so neither can be enforced by a test here.

**Provenance is reported as automatic and one 2026 write-up says otherwise.** `publishConfig.provenance` is set, so
it does not depend on the default either way.

## Measured while building it

- The isolation was verified by reading the resolver, not the variable: inside the suite `os.homedir()`, the
  conventional runtime home and both provider config directories all resolve inside the throwaway.
- **`TLC_HOME` was redirected without being declared**, so no guard checked it. Found by a new test that reads the
  setup module's own source and pairs every assignment with the declared list. Before it existed, a mutation
  removing a name from the list survived — the guards simply checked fewer names.
- **`check-boundaries` forbids `process.env.HOME`** so production resolves the home portably
  ([/decisions/ad-006.md](/decisions/ad-006.md)). The harness does the opposite job. One named exemption, and a test
  asserting the list is exactly one entry, because an allowlist grows by append and each append is invisible.
- **Six of the seven files knip first called unused were test fixtures** a test spawns as a child process, which no
  import graph can see. Declared as entries — a false positive left in place is how a check stops being read. The
  seventh was real: `src/core/floor/index.ts`, a barrel nobody imported.
- **The clean room found something on its first real run:** in a fresh container the install reports
  `/root/.local/bin is not on PATH`, which is the previous day's warning working on a machine that had never seen
  the tool.
- **A substring assertion cannot see logic being neutered.** The promotion checks began as inline shell, and a probe
  that wrapped one in `false &&` left the test green. They moved into `verify-promotable.mjs` with injectable probes;
  eight mutations now die, including that one.
- **The step-list test asserted args by position**, so inserting two steps rewrote a dozen unrelated lines. By label
  now, so each assertion states the one fact it owns.
- One of my own tests failed against a correct workflow: it matched the loose string `npm publish`, which appears in
  prose above the step that runs it.

### What an independent review found that I did not

Three mutants survived my own probes, and all three had the same shape: **the assertion read the script's source
instead of running it.**

- Deleting `tlc harness doctor` from the clean-room probe left every test green, because the assertion was
  `script.includes("tlc harness doctor")` and the *next* line — the version check — contains that text. Combined with
  a `doctor` forced to exit 1, the release would have proceeded. The commands are a list now, asserted element by
  element.
- The unused-export ceiling could be raised from 76 to 500 with nothing red, because the test compared the gate
  argument with the constant it came from. It asserts a literal inequality now: lowering is free, raising fails.
- Commenting out the payload assertion left every test green for the same reason. The function returns its entries
  and the caller uses them, so removing the call is a `ReferenceError` rather than a convention.

**And a real defect in the script itself.** The probe commands were joined with ` && ` and ended in
`|| echo "<message>"`. `&&` and `||` share precedence, so any failure anywhere in the chain fell into the `||` and
the compound exited 0 — which made the status check unreachable, hid the clean room's stderr entirely, and reported
every possible failure as the same wrong message. Proven:
`sh -c 'true && false && echo x | grep -q y || echo swallowed'` exits 0. It is `set -e` with one command per line
now, so the first failure is the exit status and the reason reaches the operator as itself.

**Two guards in the hermetic work had gone vacuous, in exactly the way the work was meant to prevent.** The test
written as the negative of the central claim — *nothing a suite writes can reach the operator's real directories* —
read `TLC_TEST_REAL_HOME`, which nothing set, so it returned on its first line every run. And two more built "the
real paths on this machine" from `homedir()`, which by then answers the fake, so the assertion whose message says
*points at a real path on this machine* could no longer see one. The setup captures the real home before
redirecting and publishes it; the negative assertion now fires — verified by pointing a provider directory at the
real home and watching it fail with `/home/someone/.cursor is inside the real home`.

That needed a third name list. `TLC_TEST_REAL_HOME` is written by the setup but is not a redirected destination, and
putting it in that list would have had the guards assert the operator's real home is a throwaway. One list per
behaviour, which is the same lesson `TLC_BIN_DIR` taught once already.

**The home is hermetic, and the count in my comment was wrong.** The review found eleven call sites across five
files, not four — and confirmed every one goes through `os.homedir()`, with no `os.userInfo()` and no
`HOMEDRIVE`/`HOMEPATH` anywhere, which is why redirecting the variable closes the class. It also confirmed that
nothing deletes `HOME`, which matters: libuv falls back to `getpwuid_r` when it is unset, and that would return the
real home.

**The knip blind spot is upstream, not configuration.** A canary export injected into sixteen modules was reported
in fourteen and not in `src/platform/paths.ts` or `links.ts`. A byte-identical copy of `paths.ts` at another path
*is* reported, and pointing `links.ts`'s four importers at an identical copy reports that too — same content, same
importers, different path, different answer. `knip --trace-file src/platform/paths.ts` answers
`No exports found`, while the same command on `style.ts` prints the whole tree. That is enough to open an issue
upstream rather than keep guessing.

**Three env save-and-restore helpers existed** — one per caller, each getting it right its own way. One now, in
`tools/test-env.scope.mjs`, whose signature makes `process.env.X = undefined` — which stores the string
`"undefined"` — unavailable.

**`promote.yml` claimed a mechanism it does not use.** The step was called *Use an npm that speaks OIDC* and the job
held `id-token: write`, but trusted publishing covers `npm publish` and not `dist-tag`: moving a tag needs a
registry token. The permission is gone and the comment says why.

## Not decided here

- **Property-based testing on the path functions.** It would have caught the home-claimed-as-project defect, but the
  mutation probe caught that one too, and modelling paths well is a real cost.
- **A mutation-testing tool.** The by-hand probes in this repository found six surviving mutants in two days, every
  one of them a missing test rather than a missing feature. Tooling it is a convenience, not a gap.
- **`platform/` and `contracts/` as barrel-only.** The architecture validator wants it; this repository's own checker
  permits deep imports into them by design, because they are the shared base and the rule it enforces is direction.
  Changing that is a decision, not a cleanup.
