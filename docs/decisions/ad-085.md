# AD-085 — The flake was a test measuring a file the whole machine writes to

- **status**: active

## Decision

1. **`CG-03` asserts on records carrying the fixture's own path**, not on the spool's length.
2. **An unparseable line is skipped rather than thrown on**, because a concurrent append can leave a partial one.
3. **`CG-03` is no longer recorded as unreproduced**, superseding that entry in
   [/decisions/ad-080.md](/decisions/ad-080.md).
4. **A test may drive the real runtime, but it may not assert on a value the rest of the machine can move.**

## Why

**The assertion was about the world, not about the code.** The test captured the spool's length, fired a hook for
an opted-out project, and required the length to be unchanged. That is a correct statement about the hook and an
incorrect statement about the file: `state/obs-spool.jsonl` is the cross-repository spool, and on any machine where
this harness is installed it is being appended to by the editor session that is running the suite. Measured on the
failing run: expected `151083635`, actual `151085395` — **1,760 bytes**, none of them written by the test.

**That is why it read as flaky.** It only fails when a hook fires inside the window between the two reads, which is
why six consecutive runs after the fact all passed, and why it showed up in a long suite rather than in the file on
its own. An intermittent failure whose trigger is concurrent activity is not intermittent; it is a race with an
unnamed second writer.

**The fixture path was already the key, sitting unused.** The test's last assertion checked `records[0].repo ===
root`, where `root` is a fresh `mkdtemp` directory. Nothing else on the machine writes records under that path, so
filtering by it turns a measurement of the file into a measurement of what this test caused. Both directions were
then proven: with 400 concurrent appends injected during the run, the length-based version fails on
`an opted-out project must not append` and the keyed version passes.

**Recording it as unreproduced was the right call with the evidence available, and it was also a dead end.**
[/decisions/ad-080.md](/decisions/ad-080.md) refused to invent a fix for a failure it could not reproduce, and
tested the one hypothesis it had — fixture age against the retention window — which was wrong. What it did not do
was ask who else writes the file. The rule worth keeping is the one in the decision above: the question to ask of a
flaky assertion is not "how do I make it stable" but "what else can move the value I am reading".

## Trade-offs

**The test still writes to the real spool.** `TLC_HOME` names both the runtime and the spool, so they cannot be
pointed apart without a runtime materialised in a temp directory — bundles and all. The file is append-only and
gitignored, so the cost is a few records in a developer's own obs history, which is the same trade the test made
before.

**Skipping an unparseable line could hide a malformed writer.** A record this test cares about is one it caused,
and those it parses; a corrupt line from somebody else is not its business. The obs contract check is where a
malformed producer is caught.

**Keying on the path means the test no longer notices an append with no `repo` field.** A writer that omitted it
would be invisible here. That field is required by the envelope and asserted elsewhere.

## Not decided here

- **Whether other tests assert on shared state.** This one was found by a failure, not by a search. `install.sh`'s
  four tests were the same shape and were fixed the same day for a different reason
  ([/decisions/ad-082.md](/decisions/ad-082.md)), which is two instances and enough to suspect a third.
- **A hermetic runtime for E2E tests.** Materialising one per test would remove the shared file entirely and costs
  a build per fixture.
