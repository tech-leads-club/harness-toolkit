# AD-119 — A rule's denial says whether the proof never ran or ran outside the window

- **status**: active

## Decision

1. **`missingProofs` returns `MissingProof[]` (`{proof, reason}`) instead of a bare `RuleProof[]`.** `reason`
   is `null` when no observation of the proof's kind and value exists at all — the honest, unenriched
   "missing" — and a short, factual string when one does exist but the `since` window rejected it:
   `"ran, but at a different commit"`, `"ran, but in a different session"`, or, when the project has no git
   checkout at all, `"ran, but this project is not a git checkout, so since HEAD can never be satisfied"`.
2. **`proofLabel` takes a `MissingProof` and appends the reason in parentheses when present.** `rules.decide.ts`
   is unchanged — `missing.map(proofLabel)` and `ruleMessage` both already operate on whatever `proofLabel`
   returns, so the richer input needed no caller to change.
3. **The distinction is computed from data `evaluateRules` already holds.** `readObservations` already returns
   the full recent tail before a verdict is reached ([/decisions/ad-100.md](/decisions/ad-100.md)); this reads
   it once more inside `missingProofs`, with no new store read, no new field recorded, and no new proof kind.

## Why

**Reported live.** A rule required `command(post_review.py) since HEAD`. The command had genuinely run — twice,
once per pull request — but `gh pr ready` still denied on both. The cause: the harness's `since HEAD` scoping
is (correctly) the git state of the one working directory the commands ran in, and the agent had switched
branches between running the proof and running the gated command, so the observation's own sha no longer
matched. The proof was real; the denial gave no way to tell that from "never ran" without reading
`rule-observations.jsonl` by hand — which is what answered it, this once.

**A fact, not a diagnosis, matching the standard this repository already set.** `evaluateRules` is silent when
a proof holds ([/decisions/ad-034.md](/decisions/ad-034.md)) — nothing about this changes that; the new text
only appears alongside a denial that was already happening. And it says only what is verifiably true — an
observation of this kind and value exists — never why the agent switched branches or whether that was a
mistake, the same restraint [/decisions/ad-060.md](/decisions/ad-060.md) drew between recording an environment
fact and guessing that it caused a failure.

**Generic by construction, not by discipline.** The reason depends only on `proof.since` and whether
`context.sha` is `null` — never on `proof.kind` — so it reads the same for `subagent`, `command`, `gate` and
`file` without a fifth branch to keep in sync. Verified with one test per kind asserting the identical reason
text.

## Trade-offs

**None beyond one more read of an already-loaded list.** `missingProofs` already iterated `observations` to
decide `proofSatisfied`; this adds a second, cheaper pass (`valueMatches` alone, no window check) only over
the proofs that already failed — bounded by `rule.require`'s length, not by the observation tail's.

## Not decided here

- **Naming the actual stale sha or session key in the message.** The qualitative reason ("a different commit")
  is enough to redirect an operator to re-run the proof; printing the specific old sha would need to pick one
  among possibly several stale observations and was not asked for.
