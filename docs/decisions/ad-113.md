# AD-113 — `tlc harness policy accept` resolves a relative path against root

- **status**: active

## Decision

1. **`acceptPolicySources` resolves every path against `root` before comparing.** An already-absolute
   path is unchanged; a relative one resolves the same way `path.resolve(root, path)` would.
2. **The CLI's "not diverging here" note resolves the same way**, so it does not misreport a relative
   path as unrelated once it is correctly accepted.

## Why

**An operator typed the natural thing and got refused.** `tlc harness policy accept .tlc/harness/config.json`,
run from inside the blocked repository, failed with `not a policy source` — even though that exact file,
as an absolute path, was the only thing listed as diverged one line above. `known` in
`acceptPolicySources` is a `Map` keyed by the absolute paths `policySourceFingerprint` computes; the
operator's argument was compared against it with no resolution step.

**Same command, same class of gap AD-101 already closed once.** That record fixed the *listing* side —
running from the wrong directory used to silently succeed and clear nothing. This is the *matching* side
of the identical command: a correct directory, a correct file, an unnormalized comparison. Both failures
share the trait that made AD-101 worth writing down: this is the one command whose entire job is
unblocking a live session, so its own friction is not cosmetic — it is time-critical, per AD-030's four
locks existing specifically to keep it fast and legible once the operator reaches it.

## Trade-offs

None found — resolution is strictly more permissive (an already-absolute path behaves exactly as before).

## Not decided here

- **Accepting the loader's paths with different casing or trailing separators** on platforms where that
  matters. Not reported.
