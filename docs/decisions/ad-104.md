# AD-104 — A subagent proof names the type the spawn declared, never the name the spawning agent chose

- **status**: active

## Decision

1. **`spawnSubagentType` carries only a declared type.** The host's `agent_type` is a *label* and lands in
   `spawnAgentLabel`.
2. **The spawn leaves a link.** At `tool.after` for `Agent`/`Task` — after, so a spawn the allowlist refused leaves
   nothing — the harness records `{label, type}` in `rule-spawn-links.jsonl`, beside the proof store and not in it.
3. **The stop resolves through the link.** `subagent.stop` with a label and no declared type takes the newest link
   with that label. A stop that already carries a declared type is never second-guessed.
4. **A stop with no resolvable link records the label**, degraded rather than silent — `doctor` already reports a
   proof kind that never arrives.
5. **A rule is satisfied by the declared type alone.** A label equal to a type satisfies nothing.

## Why

**Measured, on a real payload from Claude Code 2.1.238.** The spawn carried both
`subagent_type: "the-judge"` — the operator's agent definition — and `name: "judge-harness-rule"`, the string the
spawning agent invented. Every event from inside the child came back with `agent_type: "judge-harness-rule"` and
`agent_id: "ajudge-harness-rule-…"`. The stop mapping read `agent_type` first, so the recorded proof was
`judge-harness-rule`.

**Which is not a naming bug. It is the unforgeability argument failing.** AD-100 rests on the proof being
something the agent cannot manufacture ([/decisions/ad-100.md](/decisions/ad-100.md)). A `name` is free text
chosen by the agent being gated, so `general-purpose` named `the-judge` would have satisfied
`require: subagent(the-judge)`. The declared type is bounded by the operator's own agent registry — the host
resolves it against `agents/` and refuses what is not there — which is what makes it usable as a fact.

**The documentation says the same thing, and it is why precedence alone cannot fix this.** The hooks reference
lists `agent_id` and `agent_type` as the common fields of `SubagentStart`/`SubagentStop`, describes `agent_type` as
the agent *name*, and documents no `subagent_type` on a hook payload at all — that field belongs to the Agent/Task
tool's *invocation input*. So the authoritative type exists only at the spawn, and the only moment that proves the
subagent finished is the stop. Two events, one fact: it has to be correlated.

**And the spawn is not the completion.** Measured in the same session: `tool.after` for the `Agent` tool arrived at
16:04:47 and the stop at 16:06:03, because this host runs the subagent in the background and the tool call returns
immediately. Recording the proof at the spawn would accept a spawn-and-abandon.

**A second file, not a second record shape.** Every reader of the proof store treats a record as proof. A link is
not proof, and a reader that had to skip records is one refactor away from counting one.

## Trade-offs

**The link is per project and bounded by the same tail as the proofs.** A label reused across a long session
resolves to the newest spawn that used it, which is the same "a proof is about now" rule the rest of the feature
follows.

**A host that fires a stop with no spawn we saw degrades to the label.** Three open issues on the vendor's tracker
describe exactly that territory — a stop that cannot say which subagent finished, `agent_id` present on some events
and not others, and a version where an Agent-tool spawn fired no stop hook at all. The degraded path is where such
a host lands, and `doctor` names the proof kind that never arrives.

**The quality of the review is still not enforceable.** A spawn may declare `the-judge` and give it a lazy prompt.
The gate proves a reviewer of that type ran over this code, which is what a deterministic check can say.

**Cursor is untouched.** Its stop payload names the field `subagent_type`, which is a declared type, so it takes
the direct path. Whether it also carries a name was not measured, and nothing here assumes it does.

## Not decided here

- **Correlating by `agent_id` instead of the label.** The id appears on the child's events and on the stop, but the
  spawn's input does not carry it — the host mints it. Nothing here can link an id the spawn never saw.
- **Refusing a spawn whose name shadows a registered type.** It is tempting and it is a different rail: naming is
  not the offence, trusting the name was.
- **A proof that the review said something.** Unchanged from
  [/decisions/ad-100.md](/decisions/ad-100.md): existence, never a verdict.
