# AD-095 — Four defects about where things are written, and one of them made every hook run twice

- **status**: active

## Decision

1. **The project shim's precedence is decided from disk**, not from an environment variable. It stands down when a
   user-level document already runs the same handler.
2. **`shim` is not part of that comparison.** The same handler reached two ways is the same handler.
3. **`init` ignores the shims it writes**, and the ignore list is derived from the list the wiring writes to.
4. **`install` and `update` link the init skill through one function**, into every provider config directory that
   exists.
5. **`doctor` reports a skill link per provider**, with `dangling`, `outside-runtime` and `absent` told apart.

## Why

**The question came from a user and three quarters of the answer was "by design".** They asked why the harness had
written `.claude/`, `.cursor/hooks.json`, `.cursor/rules/` and `.tlc/` into their repository instead of globally.
The install is global; the *init* is per project, and those four are what it creates — the policy the team shares,
two project shims pointing at the global runtime, and the lessons rendered as an editor rule. It is documented in
`docs/init.md` and the README. What the question actually surfaced was the fourth thing on their list, from a much
older version, and three defects nobody had asked about.

**The guard against double-firing read a variable nothing ever set.** `shim.ts` had
`if (process.env.TLC_ACTIVE === "1")`, and `TLC_ACTIVE` is read in two places in this repository and written in
none. Four documents state that the user-level `sessionStart` hook sets it —
`docs/architecture.md` word for word — and none of them could: a hook cannot export an environment variable to a
later hook process, because each is a separate process and the host's own documentation says no field passes state
between invocations. So the condition was never true.

**Which means both levels ran the handler, on every event they share.** Measured on one machine: eleven hook groups
at user level, six at project level, six overlapping — `SessionStart`, `SessionEnd`, `PreToolUse`, `Stop`,
`SubagentStart`, `MessageDisplay`. The host merges rather than replaces, and deduplicates only a byte-identical
handler; ours differ by construction, because the project shim runs `tlc-exec.mjs shim stop` and the user hook runs
`tlc-exec.mjs stop`. That is why the dedupe misses them, and why `shim` had to come out of the comparison.

**It explains two things that were already being paid for.** Each `Stop` counted two loops against a grind cap of
three, which is how a loop counter reached 106 on a session key from three weeks earlier. And two processes wrote
the same `handoff.json` in the same event — the concurrent-write `EPERM` on the lock fixed the same day
([/decisions/ad-086.md](/decisions/ad-086.md)) is exactly that collision.

**The protection against committing a per-machine path existed here and was never shipped.** `init` writes two shim
documents containing an absolute path to the runtime on the machine that ran it, and added one line to the user's
`.gitignore`: the state directory. This repository has ignored both shims by hand since 2026-07-30 — commit
`81c5830`, "keep generated shims out of git", with the comment "per-machine artefacts rather than shared
configuration". So a user commits a settings document naming their own home directory, and the next developer's
hook points at a path that does not exist, while the repository that produced the tool had protected itself months
earlier.

**`install.sh` and `update` disagreed about where the skill goes, and the wrong one was in the command people run
more often.** The installer loops over every provider config directory that exists, "because each provider only
reads its own skills directory". `update` linked to `<runtime-home>/../skills/harness-init` — a directory no
provider reads and which did not exist at all on the machine where this was found. The evidence that it bites was
sitting there: a skill link pointing into a `/tmp` recovery directory that does not survive a reboot, so that
provider would silently never route a request to the init skill again.

**A link that resolves nowhere reads as installed to anything that only checks the link.** Hence three states
rather than a boolean, and `outside-runtime` reported even while it works — a source that is not the runtime is a
source that will move.

## Trade-offs

**The shim reads a JSON document on every invocation.** Two paths tried, first hit wins, and the hot path is
about a millisecond with Bun. It is the price of a decision that cannot be carried in the environment, and the
alternative — a state file written per session — adds a writer to every event instead of a reader.

**The shim does not know which provider invoked it, so it asks both.** A setup with one editor installed globally
and the other only in the project therefore under-runs rather than double-runs. That is the safe direction, and the
precise alternative is passing the provider into the shim, which changes every document `init` writes.

**`outside-runtime` will fire for contributors.** Anyone whose runtime is a link to their own clone gets a `FAIL`
on a link that works for them today. It is the correct reading — that path is theirs, not the runtime's — and it is
noise for the people most likely to see it.

**The ignore list changes behaviour for existing projects.** A repository that already committed its shims will see
them ignored but still tracked, because `.gitignore` does not untrack. The message says what was added and nothing
removes a tracked file on the operator's behalf.

## Not decided here

- **Whether the project shim should exist at all.** It has one real use — `docs/architecture.md`: a cloud agent
  with no user-level install runs the real handler through it — and outside that case it is a duplicate that now
  stands down. Removing it would remove that case.
- **Untracking shims already committed.** Detectable, and deleting a tracked file because a tool decided to is not
  something to do without asking.
- **Whether `.cursor/rules/harness-lessons.mdc` belongs in the same ignore list.** It is generated too, but it is
  content rather than a per-machine path, and a team may want it reviewed.
- **The grind-cap counter that reached 106.** Halving the double-count fixes the rate, not the counter that
  outlived the condition it measured.
