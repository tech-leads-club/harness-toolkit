# AD-147 — explicit Codex provider routing and batch edit paths

- **status**: active

## Decision

Add a Codex provider using local lifecycle command hooks. Installation merges handlers into the resolved
user hooks file and leaves enablement and trust review to the operator. The launcher adds a provider tag
from its explicit command-line argument. Patch paths are normalized at the adapter boundary and dispatched
individually through the existing guards, including the paused floor. Stop text supplies structured claims
on hosts without a separate response hook.

## Why

The Codex and Claude hook envelopes overlap, so field-based inference would route valid events to the wrong
adapter. Codex edits can affect multiple files; checking one path loses protection for later files and rename
destinations. Existing guard logic consumes absolute single-file paths, so the adapter and dispatcher supply
that shape without teaching core a vendor name or patch grammar.

## Trade-offs

The shared dispatcher runs handlers per affected path. Unsupported ask decisions deny, output rewriting
remains unavailable, and subagent-start decisions are informational. Hook registration is not proof of trust
or runtime enforcement. Installation preserves foreign handlers and refuses malformed configuration.

## Not decided here

Cloud orchestration, transcript parsing, usage/effort inference, and complete interception of interactive shells
or hosted tools. See [/providers/codex.md](/providers/codex.md) for the supported scope and limits.
