# AD-127 — A declared reason may name which reason it is, so the comment gate matches the code it polices

- **status**: active

## Decision

`DECLARED_REASON` (`src/core/comment-policy/comment-policy.service.ts:51`) accepts a phrase between the marker
word and its colon:

```
/^\s*(?:\/\/|\/\*|\*|#)\s*(?:why|hazard|invariant)\b[^:\n]{0,60}:\s*\S/i
```

Both forms are now a declared reason:

| Form | Example | Before | After |
| --- | --- | --- | --- |
| bare | `// why: git rename detection breaks above 50% similarity` | declared | declared |
| phrase | `// why a rewrite renders as silence: the host documents no substitution` | undeclared | declared |

Three guards keep the widening from admitting narration, each with a test:

| Guard | Rejects |
| --- | --- |
| `\b` after the marker word | `// whyever this is not a marker`, `// hazardous chemicals are stored in the warehouse table` |
| `[^:\n]{0,60}` ceiling | a sentence long enough to reach an incidental colon |
| `\s*\S` after the colon | `// why a rewrite renders as silence:` with nothing following it |

[/decisions/ad-051.md](/decisions/ad-051.md) said the reason must *open* with `why:`, `hazard:` or `invariant:`.
That clause is narrowed here: the reason must open with the marker *word*, and what follows the colon still has
to be a reason.

## Why

**The rule was split against the code it polices.** 1820 comments use the bare marker and 245 use the phrase
form. The 245 were never exempted on purpose — they pass only when a `/**` block attaches to an identifier,
because `judge` sends that case to `isInformativeDoc` and never reaches `DECLARED_REASON`. Attached to a `case`
clause, a `switch`, or written as `//` lines, the identical sentence was refused. A gate whose verdict depends on
what the comment happens to sit above is not enforcing the convention it names.

**The phrase carries information the bare marker cannot.** In a file with several declared comments, `why:`
repeated four times makes the reader match each to its subject; `why a rewrite renders as silence:` and `why the
length rule is skipped:` say which question is being answered. The convention exists so a reader learns something
the code cannot tell them, and the phrase is part of that.

**Widening a gate is the direction that needs the guards, so they are tested first.** The risk is admitting
narration that opens with the word `why`. Three tests pin the boundary — the phrase form passes, four narration
shapes are still refused, and a marker whose colon sits past the ceiling is refused — and they were written
before the regex changed, so the failure they caught was the real one.

## Trade-offs

**A 60-character ceiling is arbitrary, and picked the same way AD-051 picked four words.** It is long enough for
every phrase form in this repository and short enough that a sentence reaching an incidental colon is refused.
A comment that wants more than 60 characters before its colon is a comment whose first line is too long.

**The rule is now two-tier, and a reader has to know both tiers.** `why:` is still the shortest compliant form
and still the right one when the subject is obvious from the line below. The phrase form is for when it is not.
Neither is preferred by the checker, which is the honest position — it cannot judge which reads better.

## Not decided here

- **Whether the 245 existing prose comments should be rewritten.** They are compliant as they stand now. This
  record makes them legal, not preferred.
- **The doc-comment branch's separate standard.** A `/**` block attached to an identifier is still judged on
  informativeness rather than on a marker. That asymmetry is what exposed this defect, and narrowing it is a
  larger change than this one.
- **Whether `hazard:` and `invariant:` want their own guidance.** Both take the phrase form here for symmetry;
  whether a hazard benefits from naming its subject the way a why does is untested.
