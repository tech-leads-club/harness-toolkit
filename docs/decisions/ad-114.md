# AD-114 — Rule proof `since HEAD` resolves sha from the event's own working directory, not the project root

- **status**: active

## Decision

1. **`HarnessEvent` gains an optional `cwd` field**, populated by each provider adapter from
   whatever per-event working-directory signal the host actually reports: Claude's raw
   payload `cwd` on every event kind; Cursor's raw payload `cwd` on `shell.before` only —
   the one Cursor event kind confirmed to carry it. Absent everywhere else (never guessed).
2. **A new `shaScopeRoot(event)` helper (`src/entrypoints/support.ts`) resolves
   `event.cwd ?? event.projectDir`.** Every `currentGitSha` call that feeds the rules
   engine's proof sha (`tool-before.ts` `rulesDecision`, the observation-recording sha in
   `support.ts`, and `stop.ts`'s `observeGateForRules`/`decideStopRules`) passes this
   instead of `event.projectDir` directly.
3. **`event.projectDir` keeps every other meaning it has today.** Policy config, rule
   file location, `.tlc/harness/state`, presence tracking, gate execution and locking all
   stay anchored to it, unchanged.

## Why

**Confirmed against the official host docs.** `code.claude.com/docs/en/hooks`: *"`cwd`
follows Claude: the `cwd` field in the hook's input JSON is the worktree root after
Claude enters a worktree, and the new directory after Claude runs `cd`."* and
*"`${CLAUDE_PROJECT_DIR}` stays put: it still points at the project root where the
session started."* `event.projectDir` prefers `CLAUDE_PROJECT_DIR` — the field the host
itself documents as not moving into a worktree.

**Measured on real production state, not theorized.** One long-running session worked
across many `.claude/worktrees/<branch>` directories over several days. Every
`subagent(the-judge)` observation it recorded carried the identical sha `55f4515e` —
the main checkout's own frozen, detached HEAD — regardless of which worktree or branch
the-judge had actually reviewed, because `currentGitSha(event.projectDir)` ran in the
main checkout every time. When a `pr-open` event fired `gh pr create` from a worktree
whose real HEAD was `9e1dbae5`, its proof check computed `context.sha` the same wrong
way, landing on `55f4515e` too. `observation.sha === context.sha` matched — not because
the review was fresh, but because both sides read the wrong, identical, stale directory.
The `review-before-pr` rule (`otherwise: deny`) allowed a PR through with zero review of
its actual commit. Reproduced live: invoking the installed `tlc-exec.mjs tool-before`
directly against the affected worktree, with the affected session's real state, returned
`{"permissionDecision":"allow"}` for a `gh pr create` with no matching proof for that
worktree's HEAD.

**Worktrees are a known gap class in the host itself**, not a harness-specific edge case:
`anthropics/claude-code#46808` and `#36360` document related worktree/project-root
resolution issues in Claude Code's own hook and settings loading. This harness reads the
field each host actually reports (`cwd`) rather than working around a class of host bug
with a heuristic.

**Cursor confirmed separately.** `cursor.com/docs/hooks` documents `cwd` only on
`beforeShellExecution` — not on `afterShellExecution`, `afterFileEdit`, `subagentStop`,
or any other event. `pr-open` and `commit`/`push` triggers are shell events, so this is
exactly the event kind the fix needs for Cursor too.

## Trade-offs

`event.cwd` is `undefined` for Cursor event kinds other than `shell.before` (no source
field exists there), and for any malformed/legacy payload. Callers fall back to
`event.projectDir` in those cases — byte-identical to before this change. Cursor's docs
do not confirm `cwd` tracks a worktree/`cd` as explicitly as Claude's do; this is still
strictly more correct than the prior behavior (a fixed project root that provably never
tracks worktree HEAD), never worse.

## Not decided here

- **`turn_base_sha` in `prompt-submit.ts`** (used to scope stop-time gate diffs, AD-058)
  has the same root cause and is plausibly wrong inside a worktree too. Not fixed here —
  different subsystem (gate diffing, not rule proof), different, unverified blast radius.
  `shaScopeRoot` is reusable verbatim if this is picked up later.
- **Retroactively correcting historical `rule-observations.jsonl` records** written with
  the wrong sha. An operator/ops decision, not a code change.
